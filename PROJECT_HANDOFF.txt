SCIENTIFIC IDEA
---------------
"Gotham Loops" is being developed as a general framework for bounded novelty:

  maximize or study heterogeneity / novelty
  subject to preserving a salient structural relationship.

The first implemented statistical version uses a balanced one-way ANOVA ICC as the
structural criterion.

Motivating question:

  Given grouped data already observed, what can the next observation in each group
  look like if the new observations are as heterogeneous as possible while preserving
  a specified ICC threshold?

A complementary question is:

  What profiles lie just across that threshold, within an epsilon band, and therefore
  break the chosen grouping criterion by only a small amount?

This creates a geometry of a structural decision boundary rather than treating the ICC
threshold as only a scalar cutoff.


CURRENT MATHEMATICAL MODEL
--------------------------
Current scope:
  - G balanced groups
  - common current group size n
  - one proposed new observation per group
  - one-way ANOVA / random-intercept ICC
  - frontier calculations currently focus on centered proposals with mean deviation 0

For current group g:

  group mean:
    ybar_g

  grand mean:
    ybar

  current group offset:
    a_g = ybar_g - ybar

A proposed next observation is represented as:

  x_g = ybar_g + d_g

where d_g is the proposal deviation from the current group mean.

The balanced one-way ANOVA ICC used by the package is:

  ICC = (MS_between - MS_within) /
        (MS_between + (n - 1) * MS_within)

Negative estimated ICC values are retained rather than truncated to 0.


ANALYTIC UPDATE IDENTITIES
--------------------------
If one proposed observation is added to each group, with current common group size n:

  SS_within_new
    = SS_within
      + n / (n + 1) * sum_g(d_g^2)

Let:

  dbar = mean(d_g)
  d_cg = d_g - dbar

Then:

  SS_between_new
    = (n + 1) *
      sum_g[
        a_g + d_cg / (n + 1)
      ]^2

These identities are implemented analytically and tested against physically appending
the proposed observations and recomputing the ANOVA state from raw data.


GOTHAM GEOMETRY
---------------
For centered proposal deviations:

  dbar = 0

define:

  r = ||d||

as proposal heterogeneity magnitude, and:

  c = cos(theta)
    = (a' d) / (||a|| ||d||)

as alignment with the existing between-group structure.

Interpretation:

  c = -1
    proposal directly opposes the existing group ordering / separation

  c = 0
    proposal is orthogonal to the existing group-offset vector

  c = 1
    proposal directly reinforces the existing group ordering / separation

A key result already demonstrated:

  the same magnitude of within-group heterogeneity can have very different effects on
  the ICC depending on alignment.

Therefore "maximally heterogeneous while preserving grouping" cannot be defined by
magnitude alone. Direction relative to the existing grouping structure matters.


IMPLEMENTED PACKAGE FUNCTIONS
-----------------------------
Current exported/public-facing functions developed in this milestone:

1. anova_icc()
   - balanced one-way ANOVA ICC
   - retains negative estimates
   - rejects unbalanced/invalid input for this first formulation

2. gotham_state()
   - summarizes the current balanced grouped dataset
   - returns:
       n_groups
       group_size
       grand_mean
       group_means
       group_offsets
       group_offset_ss
       ss_between
       ss_within
       ms_between
       ms_within
       icc

   where:
       group_offset_ss = sum_g(a_g^2) = ||a||^2

3. gotham_update()
   - analytically updates the ANOVA state after one proposed observation per group
   - proposal deviations are d_g = x_g - ybar_g
   - records proposal geometry including:
       deviations
       mean_deviation
       centered_deviations
       deviation_ss
       centered_deviation_ss
       alignment

4. gotham_frontier()
   - solves the ICC threshold boundary analytically for centered proposals
   - parameterization:
       radius r
       alignment c
   - solves for the first/possible positive threshold crossings
   - allows no finite root, one root, or two roots
   - do NOT assume globally that every direction has exactly one crossing

5. gotham_profile()
   - constructs one deterministic representative observation/deviation profile for a
     requested radius and alignment
   - many microstates can share the same macrostate (r, c)

6. gotham_profile_set()
   - generates concrete representative profiles at:
       threshold + epsilon
       threshold
       threshold - epsilon
   - makes the "just preserves / boundary / just breaks" idea tangible

7. gotham_band()
   - maps an ICC-scale epsilon band into observation-space radial distances
   - quantifies local boundary width / fragility along a chosen alignment direction

8. gotham_sequence()
   - repeatedly takes the CURRENT state
   - finds the first ICC frontier crossing along a fixed requested alignment
   - generates the corresponding threshold profile
   - adds one new observation per group analytically
   - repeats
   - every completed step is designed to return to the same ICC threshold

IMPORTANT:
  gotham_sequence() currently follows the FIRST frontier crossing along each ray.
  Do not casually describe this as the globally largest possible admissible radius in
  cases where a direction could have multiple crossings / re-entry.

SEQUENTIAL GOTHAM RESULT
------------------------
The first sequential experiment used:

  threshold = 0.80
  steps = 5

with fixed alignments:

  -1
   0
  +1

Every completed step returned to:

  ICC_after = 0.80

but the data geometry evolved very differently.


A. OPPOSING SEQUENCE: alignment = -1

  step   radius      group_offset_ss_before   group_offset_ss_after
    1    3.026088          18.000000              12.153023
    2    1.460399          12.153023              10.201884

    4    1.177492           8.871260               7.897522
    5    1.091238           7.897522               7.149464

Interpretation:
  - repeated threshold-hugging novelty that opposes current group structure collapses

  - after the first step, progressively smaller proposal radii are sufficient to return

B. ORTHOGONAL SEQUENCE: alignment = 0

  step   radius      group_offset_ss_before   group_offset_ss_after

  - orthogonal proposals do not preserve group_offset_ss exactly
  - the cross-product with the existing structure is zero, but the squared magnitude of

  - group_offset_ss therefore grows modestly

  step   radius      group_offset_ss_before   group_offset_ss_after

  - repeated threshold-hugging novelty aligned with current group structure dramatically

  - the admissible threshold radius grows rapidly

A SECOND IMPORTANT SEQUENTIAL RESULT
------------------------------------
At step 1:

  ICC_before  = 0.8965517
  ICC_at_zero = 0.9298246

At subsequent steps, ICC_before is exactly 0.80 but adding an observation exactly at
each current group mean would temporarily raise the ICC:

  step 2: ICC_at_zero = 0.8453608
  step 3: ICC_at_zero = 0.8356164
  step 4: ICC_at_zero = 0.8292683
  step 5: ICC_at_zero = 0.8248175

Thus each step creates some "room" for additional heterogeneity before returning to the
same threshold.

This is a consequence of adding observations at the group means without adding
within-group sum of squares while group size changes.


CURRENT SCIENTIFIC TAKEAWAY
---------------------------
The strongest result so far is:

  A fixed ICC threshold does not define a single amount of allowable heterogeneity.

Instead, the admissible amount depends strongly on the DIRECTION of the new observations
relative to the existing between-group structure.

Moreover, under a sequential threshold-hugging process:

  the same ICC_after = 0.80 can coexist with radically different evolving data
  geometries.

After five steps in the canonical example:

  opposing:
    group_offset_ss = 7.149464

  orthogonal:
    group_offset_ss = 20.158680

  reinforcing:
    group_offset_ss = 131.728031

So datasets can satisfy the exact same low-order grouping criterion while having very
different structural histories and geometries.

This is likely more scientifically interesting than simply characterizing one static
ICC threshold.


IMPORTANT TERMINOLOGY / INTERPRETATION CAUTIONS
-----------------------------------------------
1. ICC is being used here as the first salient grouping statistic, not claimed to be
   universally the correct decision criterion.

2. The first package formulation is deliberately balanced and one-way.

3. Current frontier work is primarily for centered proposals (mean deviation = 0).

4. "Alignment" is with the current vector of group offsets from the grand mean.

5. gotham_profile() returns a representative microstate. Many actual observation
   vectors can share the same (radius, alignment) macrostate.

6. gotham_sequence() follows the FIRST threshold crossing along the chosen alignment
   direction. Because gotham_frontier() allows two-root cases, avoid calling this
   globally "the maximum possible heterogeneity" without checking the frontier topology.

7. The .80 threshold and .02 epsilon used in examples are illustrative, not asserted as
   universal education-research standards.
